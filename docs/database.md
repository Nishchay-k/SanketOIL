# Database and migrations

PostgreSQL is the application database. SQLAlchemy models live in `backend/app/models.py`; Alembic revisions live in `backend/migrations/versions/`.

## Required PostgreSQL extensions

- **PostGIS** stores well coordinates as `geography(POINT, 4326)` and supports radius queries.
- **pgvector** stores optional local sentence embeddings for semantic document search.

The initial Alembic revision enables both extensions and creates the model tables and search indexes. The database account must be allowed to use these extensions. Supabase users can enable them in the project's database extensions settings if needed.

Apply migrations before starting a production deployment:

```sh
python -m alembic upgrade head
```

Render runs this command through `preDeployCommand`. Production uses `AUTO_CREATE_SCHEMA=false`; the application never creates or changes production tables at startup.

## Data tables

The schema keeps wells, formation intervals, surveys, drilling events, telemetry, risk predictions, and prediction evidence. It also stores documents and page-linked chunks, extracted entities and event candidates, reservoir and drilling-program context, alert status, and model-version notes.

Uploaded file bytes live in Supabase Storage in production. The `documents` row stores the bucket object key and storage backend. The bucket should be private; API downloads use short-lived signed URLs.

## Move a local SQLite database

The import helper copies records from the previous SANKET SQLite schema into a migrated PostgreSQL database in foreign-key order. It copies matching columns, preserves record identifiers, and advances generated ID sequences.

```sh
python scripts/migrate_sqlite_to_postgres.py data/nwis.sqlite3
```

Set `DATABASE_URL` to the target PostgreSQL database first. For production import, also set `APP_ENV=production`, `AUTH_MODE=supabase`, and `STORAGE_BACKEND=supabase` with the Supabase credentials. The helper copies each document file from `data/documents/` into the configured private bucket. It stops if a referenced local file is missing. Keep a backup of the SQLite database and document directory until the imported record counts and files are checked.

The PostgreSQL target must be empty before import to prevent collisions with existing wells. Database rows are copied in one transaction. If the import fails, that transaction rolls back and any uploaded Supabase objects are removed. The source SQLite database and document directory are left untouched.

## Search indexes

Document chunks have a PostgreSQL GIN full-text index. A partial HNSW index supports cosine search when stored vectors exist. Existing keyword, structured, and explainable retrieval continues when no embedding model is configured.

No vector is generated by default. To add vector retrieval, install a compatible local sentence-transformer model, set `NWIS_EMBEDDING_MODEL` to its local directory, and match `VECTOR_DIMENSIONS` to that model's output. The model is not downloaded or called from an external AI service.

## Development data

Development mode seeds fictional records on an empty database when `SEED_DEMO_DATA=true`. Production disables seeding. The regression tests use temporary SQLite databases only for fast isolated checks; production and Compose use PostgreSQL.
